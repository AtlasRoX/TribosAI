## 2. Changes

### 2.1 Result consistency and verification (issues 1-4)

- `tribos/verify/latex_math.py` (new): a LaTeX/plain-math parser that builds SymPy expressions directly (no `eval`,
  no SymPy string parsing): fractions, roots, powers, sub/superscripts, Greek, functions with and without backslash,
  implicit multiplication, `\dot x`/`x'`/`dx/dt` derivatives, function application, definite integrals and sums.
  Unsupported notation (`\pm`, matrices, limits) raises `Unsupported`, which makes a statement *not checkable*, never
  wrong.
- `tribos/verify/math_claims.py` (new): the deterministic audit of the final answer's mathematical statements.
  Relation chains are read from inline/display math and table rows; the question's values are bound first; the
  answer's definitions bind in document order (a restatement is checked, never rebinds); derivatives are always
  computed from the bound function; equations with unknowns wait until their unknowns are stated; a stated value of a
  quantity a tool computed is cross-checked against the tool (`tool:<key>` provenance); the final solution is checked
  against the stated ODE, the initial conditions and the verified solution; table numbers are grounded in tool
  outputs. Tolerances follow printed precision (one unit in the last place), exact forms are bound when a chain
  holds, and rounding of bound decimals is propagated by sensitivity. Hypothetical statements ("if c = 0 ...") are
  skipped. Outcomes: passed / failed / inconclusive / unsupported; definitions are recorded but are not claims.
- `tribos/verify/result_record.py` (new): the typed, versioned `ResultRecord` (problem, given values and units,
  expressions, quantities with formula, symbol and convention, solver runs, provenance) with a content-hash revision.
  `finalize.assemble_result` stores it as `execution_artifacts["result_record"]`, stamped with the verified answer
  hash and the revision the check used; exports write it as `result_record.json`.
- `tribos/verify/verifier.py`: the audit runs inside `verify_response` after the final rewrite (and after every
  revision); contradicted statements are CRITICAL `MATH_CONSISTENCY` defects with the computed value as the
  correction, so the existing bounded correction loop sends them back to the writer; the report gains `coverage`
  (extracted, evaluated, passed, failed, unsupported, inconclusive), `status` (verified | checked | failed |
  not_evaluated), `math_audit`, `answer_hash`, `record_revision`; `fully_verified` requires evaluated claims.
  A sentence the audit contradicted is not penalised twice by the phrase-specific amplitude/phase check.
- `tribos/agents/orchestration/verify.py`: the trace step reports coverage ("No claims could be checked" instead of
  "score 1.00"); the banner on a failing answer lists the contradicted statements.
- `tribos/agentic/confidence.py`, `tribos/agentic/math_agent.py`: the agent's benchmark precision is
  `component_confidence` scoped to its final expression; `answer_confidence` is no longer set from it; the writer is
  told the scope and not to re-derive numbers in prose.

### 2.2 Execution, recovery and completeness (issues 5-7)

- `tribos/agentic/plan_graph.py`: node-level `timeout_s` (from the node or deadline fields written into args); a
  deadline field becomes the tool's own timeout argument when its schema has one (`timeout_seconds -> timeout_s`),
  otherwise the node's deadline, always recorded in `node.adjusted`; `recovered_by` on nodes.
- `tribos/agentic/executor.py`: resolved arguments (references filled in) are validated against the tool schema
  before dispatch; a violation is "rejected before dispatch" with an actionable message (an over-long script reports
  its length and the `inputs` channel); the node deadline is enforced (grace only for tools with their own timeout).
- `tribos/extensions/sandbox.py`, `tribos/agentic/sandbox/runner.py`: `inputs` (JSON, up to 2,000,000 characters) is
  passed to the script as the variable `inputs`; the code limit is back to 20,000 characters; the computation id
  covers the data.
- `tribos/agentic/planner.py`: the planner is told where controls and data go.
- `tribos/agentic/plan_execute.py`: `link_recoveries` links a failed node to the later successful node of the same
  tool and purpose and marks the failed result `recovered_by`.
- `tribos/agents/authoritative_orchestrator.py` (`_task_outcome`): recovered failures are excluded from "partial" and
  reported as history; unresolved failures are listed with their effect; grounding is `not_checked` when nothing was
  evaluated. `TaskOutcome` gains `recovered_failures`, `unresolved_failures`, `deliverables`.
- `tribos/agents/deliverables.py` (new) and `finalize.apply_deliverables`: the requested items are read from the
  question; a requested quantity that is missing or stated with a contradicted value makes the answer partial with
  that reason; prose requests are listed only.

### 2.3 Scientific reporting, retrieval and memory (issues 8-11)

- `tribos/dynamis/engine.py`: dense output; `extrema` per state (sampled and dense min/max with their times) and
  `solver` (method, rtol, atol, output samples and spacing, internal steps, function evaluations).
- `tribos/dynamis/stated_ode.py` (`stated_units`) and `gather.py`: units from the question's own values label the
  stated ODE's trajectories.
- `tribos/archivon/grading.py`: the registry work type decides the document type first (book chapter, book,
  proceedings, report); a DOI without a journal venue is "unknown", not peer-reviewed; grades carry
  `document_type`, `publication_status`, `peer_review`, `metadata_source`; `peer_reviewed` is labelled "Journal
  article" (review not verified).
- `tribos/archivon/engine.py`: model-variant penalty (quantum, fractional, nonlinear, Coulomb, Duffing, market, ...
  when the query does not use them), a relevance floor with a limitation note, per-passage `model_variant`,
  `term_coverage` and document-type fields; years are never printed as "None".
- `tribos/utils/memory/research_memory.py`: a turn whose checks evaluated nothing stores nothing as verified;
  contradicted statements are stored as REFUTED "do not reuse" nodes and the dialogue turn is annotated; literature
  passages are labelled as retrieved, not reviewed; `requalify_legacy_verified()` requalifies evidence stored as
  verified under the old policy (content and provenance kept, reason in `contradiction_notes`).

### 2.4 Interface and performance (issue 12)

- `web/src/lib/verificationState.ts`, `VerificationNotice.tsx`: a "not evaluated" state; inconclusive claims are
  counted apart from findings; contradicted statements are listed first; the task notice shows recovered attempts,
  unresolved failures with their effect, and the requested items with their status.
- `MathAgentArtifact.tsx`: "Benchmark precision 98% (n=43)" with its scope instead of "98% calibrated";
  `MessageArtifacts.tsx`: the Verification tab badge is the checked-claims count unless a whole-answer probability
  exists; `ClaimConfidenceArtifact.tsx` states the scope and the statement checks.
- `EvidenceSources.tsx`: groups for every backend document type (book chapters, conference papers, books, reports),
  "Journal articles" instead of "Peer-reviewed articles", the first 12 works with "Show all".
- `SimulationArtifact.tsx`, `TrajectoryCharts.tsx`: "Min/Max (samples)" and "Min/Max (dense)" columns, a caveat with
  the solver's internal steps, units on charts and tables.
- `AgentRunPanel.tsx` and `finalize.stage_seconds`: non-overlapping time per kind of work (planning, retrieval,
  execution, drafting, verification).
- `ode_verification.ENGINEERING_REPORT_NOTE`: the answer gives the key numbers and points to the Numerical
  verification card instead of repeating its tables.
- `thoughts.mergeThought`: a delayed or replayed "running" step update never reopens a finished step.
- Exports (`tribos/export/report_model.py`, `bundle.py`): coverage, status, revisions; no score line when nothing was
  evaluated; task completeness details; `result_record.json`.

## 4. Remaining limitations

- **Coverage is partial by design.** The audit reads LaTeX math and result tables. Statements written only in prose
  ("the time constant is 4/3 s"), `\pm`, `\lim`, matrices and some derivative notations (`\frac{\mathrm d}{\mathrm{dt}}`)
  are not checked; they count as not checkable or are not extracted. On the three live answers 4-5 of ~50 statements
  stayed inconclusive (characteristic roots with `\pm`, the homogeneous ODE written in a generic unknown, an energy
  balance at a symbolic final time T).
- **False alarms are measured, not excluded.** The capability matrix and the three real live answers have no false
  alarm; each live run before the last fixes exposed one (now pinned by tests). New writing styles can still produce
  one; a contradicted statement fails verification and triggers one correction round, so a false alarm costs latency
  and shows a warning on a correct answer.
- **Heuristics.** Hypothetical and reference statements are recognised from a short list of cue words; deferred
  equations resolve only within their heading; quantity cross-checks against tool values need the quantity's name in
  the surrounding words. These choices trade coverage for no false contradictions.
- **Units are not checked dimensionally.** Units are stripped (and degrees converted to radians); a value with the
  wrong unit but the right number passes. `physis_units` exists but is not wired into the audit.
- **Deliverables are read heuristically** from imperative clauses; unusual phrasing can miss an item or add a noisy
  one. Only quantity requests make an answer partial.
- **Retrieval relevance** uses a fixed list of model-variant qualifiers and a term-coverage floor; it does not judge
  passage-level support for each claim beyond the existing claim audit and NLI judge.
- **Oversized code**: the cause in the capture could not be confirmed (the payload is not in the capture). The
  pre-dispatch check, the `inputs` channel and the 20,000-character limit address both plausible causes; a planner
  can still write a long script, which is now rejected before dispatch with an actionable message.
- **Calibration**: the 98% benchmark precision is from one held-out benchmark of single problems (n = 43); it is now
  scoped to the agent's final expression and shown with n. There is no calibrated probability for whole answers.
- **Memory**: the requalification changed 36 local records; stores on other machines need
  `ResearchMemoryEngine.requalify_legacy_verified()` run once (a dry run is available).
- **Provider reliability**: two of the live runs met NVIDIA endpoint errors (connection reset, internal server error).
  The system reports these as a partial answer with the raw evidence, but cannot avoid them.
- **Pre-existing test failures**: 4 prompt-wording tests (`tests/test_answer_format.py` x3,
  `tests/test_answer_reconcile.py` x1) fail on the uncommitted STEM prompt rewrite and are unrelated to this work;
  they need a decision on the intended prompt text.
- **Not changed**: the run's 600 s default time budget at Ultra effort (the browser run used all of it); the writer
  model's own latency dominates (drafting 60-230 s per run).
