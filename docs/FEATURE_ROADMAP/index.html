    Feature roadmap: tasks for AI coding agents

    Read AGENTS.md first. It has setup, commands, architecture and conventions.

    Each task below is self-contained: a goal, where it plugs in, the files to create or own, and acceptance criteria. The tasks can be done in any order and by different agents at the same time, as long as each agent edits only its task's files. The shared files are:

    • tribos/extensions/__init__.py
    • tribos/config/settings.py
    • app/backend/main.py (router list)
    • tribos/agents/stem_evidence.py
    • web/src/components/artifacts/registry.tsx

    In the shared files, add small entries only. Do not restructure them.

    Status (2026-10-25): all ten tasks are DONE (see each section's note), committed on the features-roadmap branch in the order T8, T1, T4, T3, T2, T9, T6, T7, T5, T10 (T2 before T9 because its work was already in progress). The end-to-end run with the live model found and fixed three integration gaps: closed computations that need a specialised tool now reach the planner, the planner is told the attached files' ids, and the calculators accept the input names a model writes. One live gap remains: the planning model does not always plan the engineering-calculator call.

    Definition of done for every task:

    • New tests pass.
    • The full pytest suite stays at 0 failures.
    • ruff --select F,E9 and bandit --severity-level high are clean.
    • Web: npm run typecheck, npx eslint src (0 errors), npm test and npx next build all pass.
    • scripts/gen_env_reference.py --check passes. Run it after adding settings.

    T1: Fit ODE models to uploaded data

    Status: DONE (2026-10-25). Extended the existing fitter with safe ODE least squares, robust multi-start/bounds/initial-state fitting, covariance diagnostics, measurement loaders, agentic execution and fit/residual/CI cards. No dependencies added; intervals are local normal approximations, with singular fits explicitly unavailable. Verified: 1341 Python tests passed (15 skipped), 146 web tests passed; all gates green.

    Goal. A user attaches measurements (CSV/XLSX/HDF5/MAT: a time column plus observed state columns) and asks "fit the damped oscillator to my data", or gives ODEs with unknown parameters.

    What to build.

    1. Map dataset columns to the state variables, by name or an explicit mapping. Auto-detect the time column (t, time, …).
    2. Fit with scipy.optimize.least_squares, integrating with the Dynamis integrator. Support bounds, multi-start, a robust loss, and optionally fitting the initial conditions.
    3. Report:
    4. best-fit values, standard errors and 95% CIs, from cov = s²(JᵀJ)⁻¹;
    5. the correlation matrix;
    6. identifiability warnings: near-singular JᵀJ, |corr| > 0.95, or a CI wider than its value;
    7. RSS, RMSE, R² per observed variable, AIC and BIC;
    8. decimated residuals, and the fitted trajectory against the data.

    Where it plugs in. - tribos/dynamis/engine.py already has dynamis_fit_parameters: extend it rather than duplicate it. - Wire tribos/agentic/fit.py to run the fit whenever a dataset is attached and a system is known. Today it says fitting is not run. - Register the tools in tribos/extensions/calibration.py and tribos/extensions/dynamis.py. - Reuse the artifact key model_calibration and upgrade web/src/components/agentic/CalibrationArtifact.tsx with: a fit-vs-data plot, a residual plot, a CI table and the warnings. - Add an evidence renderer in stem_evidence.py.

    Also required by T6 and T8. Add "spec": {rhs, parameters, initial_state, t_span, method, model_name} to every dynamis_simulate_ode and dynamis_parameter_scan result. These are the exact inputs that reproduce the run.

    Accept when: - Known parameters of a damped oscillator and of logistic growth are recovered from noisy synthetic data, inside their CIs. - Correlated parameters raise the warning. - Column mapping works. - spec is present on simulation results. - The agentic fit phase runs end to end with an attached dataset, using the test fakes.

    T2: PDE solver

    Status: DONE (2026-10-25). Added tribos/dynamis/pde/ (sparse operators; Crank-Nicolson/explicit/BDF heat, leapfrog wave, direct Poisson, method-of-lines advection-diffusion, Fisher-KPP and Burgers) with nested-grid convergence studies, Richardson estimates, exact discrete mass/energy checks, CFL refuse/adapt, the dynamis_solve_pde tool, evidence renderer and pde card. No dependencies added. Left out: 2D advection-diffusion, Fisher-KPP and Burgers (1D only, as specified), and mixed periodic/bounded 2D problems are solved without a convergence study.

    Goal. Dynamis only handles ODEs. Add tribos/dynamis/pde/ (numpy/scipy only) and tribos/extensions/pde.py (tool dynamis_solve_pde, domain dynamis).

    Equations, on rectangular domains: - heat/diffusion, 1D and 2D; - wave, 1D and 2D; - Poisson/Laplace, 1D and 2D; - advection-diffusion, 1D; - reaction-diffusion (Fisher-KPP), 1D; - viscous Burgers, 1D.

    Boundary and initial conditions. Dirichlet, Neumann and periodic boundary conditions. Initial conditions and sources are expressions in x, y, t, parsed with safe_expr.

    Methods. - Method of lines with solve_ivp, using BDF for stiff cases, or Crank-Nicolson for heat. - Central or leapfrog for wave, with a CFL check. - A sparse direct solve for Poisson. - Refuse or adapt unstable explicit settings, and report the stability number.

    Verification, the core value. - A mesh-convergence study at N, 2N and (when cheap) 4N, giving the observed order p, a Richardson error estimate and a "converged" flag. - Comparison with the analytic solution when one is known. - Conservation checks: mass for periodic diffusion, energy for wave.

    Output. - 1D: about 20 snapshots on the x grid. - 2D: grids of at most 80×80. - A convergence table and probe values. - Caps on grid size and wall time, set through settings.

    UI. - Artifact key pde, card web/src/components/artifacts/PdeArtifact.tsx: a 1D line plot with a time slider, a 2D heatmap with a legend (theme-aware), the convergence table, and stability and verification badges. - Add an evidence renderer.

    Accept when: - 1D heat matches the analytic solution with order ≈ 2. - 1D wave matches d'Alembert's solution. - A 2D manufactured Poisson problem is solved. - Mass is conserved for periodic diffusion. - A CFL violation is refused or adapted. - An unsafe expression is rejected. - The planner selects the tool for "solve the heat equation on [0,1]…".

    T3: Uncertainty propagation

    Status: DONE (2026-10-25). Added tribos/physis/uncertainty.py with first-order GUM and vectorised Monte Carlo propagation, Pint unit handling, CODATA autofill, a contribution budget, the physis_propagate_uncertainty tool and the uncertainty result card. No dependencies added; a compound unit is reported by its SI name ("joule") when one exists, else by its expansion. Verified: 1356 Python tests passed (15 skipped), 151 web tests passed; all gates green.

    Goal. Add tribos/physis/uncertainty.py with the tool physis_propagate_uncertainty (domain physis).

    Inputs. - An expression, parsed with safe_expr. - Variables {name: {value, uncertainty, unit?, distribution: normal|uniform|lognormal}}. - Optional correlations.

    Methods. - linear: first-order GUM, using SymPy partial derivatives, with sensitivity coefficients and each input's percentage contribution. - monte_carlo: vectorised numpy, seedable, giving the mean, std, 95% interval and skewness. - both: runs the two and warns when they disagree, which signals nonlinearity.

    Other requirements. - Units through Pint. - Optionally fill CODATA constants (c, G, h, k_B, e, m_e, N_A, …) with their uncertainties from Physis, and say so in the output. - Format the result as value ± U with k = 2: the uncertainty to 2 significant figures, and the value rounded to match. - Artifact key uncertainty, card artifacts/UncertaintyArtifact.tsx: the result, a budget table with contribution bars, and the Monte Carlo histogram.

    Accept when: - Linear propagation for products and quotients adds relative uncertainties in quadrature. - Monte Carlo agrees with linear propagation for a linear function. - A nonlinear case produces the warning. - Units propagate. - CODATA autofill works.

    T4: Unit checking on every answer

    Status: DONE (2026-10-25). Implemented deterministic dimensional audit in tribos/verify/units_audit.py integrated into math_claims.audit_answer and VerificationNotice.tsx. Pint checks dimensional consistency, unit conversion values, and wrong unit labels; ambiguous symbols remain unevaluated. All gates and 1349 tests pass.

    What to check. Extract quantity statements and equations with units from both text and LaTeX ("F = 50 N", $E = mc^2 = 9.0\times10^{16}\,\mathrm{J}$). Bind symbols to the quantities stated in the question and the answer, then check:

    • (a) dimensional consistency, using Pint (tribos/physis/units.py);
    • (b) that a stated numeric result matches its equation after unit conversion;
    • (c) wrong unit labels, for example a pressure given in N.

    Unbound or ambiguous symbols are "not evaluated" and are never flagged.

    Output. - Results go to verification_report.units: {checked, consistent, inconsistent: [{statement, lhs_dim, rhs_dim, reason}], not_evaluated}. - A contradiction becomes a defect that is fed back to the writer, the same way math-claim failures are. - Web: show a compact "Units: N checked, M inconsistent" line in web/src/components/VerificationNotice.tsx.

    Accept when: - Wrong dimensions and wrong numeric results are caught. - Correct physics paragraphs and ambiguous symbols are not flagged. - LaTeX units (\mathrm{}, \,) are handled. - A defect is created and fed back.

    Runs. For a chat or job request with project_id, where the caller is a member: - inject the project's instructions as a delimited, spotlighted block of user-authored guidance; - auto-attach the project's files, in addition to any dataset_ids; - exclude rejected facts from recall.

    T11: Adaptive research loop, accuracy tools and thesis exports

    Status (2026-11-02): DONE. See agentic/research-loop.md.

    • Loop. Research projects (loop mode) review the literature, write a charter, run rounds of parallel tests (CodeAct with independent replication, Lean proofs, cited literature), judge them with deterministic evidence rules, and stop when concluded or stagnant. They then write a chapter-by-chapter thesis whose numbers are checked against the ledger.
    • Accuracy tools. axiom_interval_verify, axiom_precision_check, axiom_counterexample_search, calcula_cross_validate, calcula_distribution_tests.

    T13: Cheminformatics for structure questions

    Status (2026-11-07): DONE, measured on the failing items only. After T12, every remaining GPQA failure in the paired run was an organic-chemistry item, and Tribos had no chemistry tooling. The clearest failure was stereodescriptors: the model had a product's geometry right and still wrote the wrong R/S labels.

    • Structure facts (physis_molecule, tribos/physis/chemistry.py, RDKit 2026.3.6):
    • formula, masses and degree of unsaturation;
    • stereocentres with CIP labels (r/s included), chiral or meso;
    • stereoisomer counts as enantiomer pairs and achiral forms;
    • distinct H and C environments;
    • the relation between two structures.
    • Descriptors to geometry (physis_stereo): a descriptor set is assigned with the CIP rules and embedded in 3D. For every ring, the tool lists which substituents share a face (cis/trans, syn/anti, endo/exo).

    T14: Chemeia, a chemistry agent

    Status (2026-11-07): DONE, measured on GPQA's organic-chemistry items. tribos/agentic/chem_agent.py (TRIBOS_CHEM_AGENT, on by default) is an augment-stage phase for organic-chemistry questions (is_organic_question).

    How a run goes:

    1. The model works the reaction as JSON: each intermediate and the target compound as SMILES (the target may be the product, a starting material or a reagent), the geometry, the chosen answer and the decisive chemistry.
    2. Code (RDKit) parses every structure and computes formulas and counts.
    3. Code matches the target to the answer options: exactly when configurations are written, otherwise by constitution. Options are built from SMILES or from their names (tribos/physis/names.py).
    4. An invalid structure, a target that matches no option, or a target that is a different option from the one chosen gets one repair round with the specific discrepancy.

    The <chem_agent> evidence states that code checked the structures, not the chemistry. With the agent on, structure questions no longer force a tool plan.
